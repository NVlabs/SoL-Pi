# Star history chart

The README chart is generated by [Update star history](https://github.com/NVlabs/SoL-Pi/actions/workflows/star-history.yml). It runs hourly at minute 17, when the generator or workflow changes on `main`, and on manual dispatch. GitHub may delay scheduled runs; the image shows the actual successful fetch time in UTC.

The workflow uses its built-in `GITHUB_TOKEN`, Node.js, and the [GitHub aggregate star history and count endpoints](https://docs.github.com/en/rest/activity/starring). It requires no additional secrets, npm installation, or third-party chart service. The history request fetches every page back to repository creation.

The line sums GitHub's daily star additions. The separately labeled current total comes from the count endpoint and excludes removed stars; it can differ from the historical sum. Daily boundaries follow GitHub's reported week timestamps and are not guaranteed to align with UTC. No stargazer identities are collected.

The light SVG, dark SVG, and source JSON are committed to the dedicated `star-history` branch. The README loads the SVGs from `raw.githubusercontent.com`; GitHub's image cache may add a short delay. The workflow does not change `main` or the website's `gh-pages` branch. Fetching, validation, and rendering finish before publication, so a failed run leaves the previous published chart available.

To refresh manually, open the workflow, select **Run workflow**, and run it on `main`. To generate a local preview, choose an output directory outside the repository and run:

```bash
node scripts/update-star-history.mjs NVlabs/SoL-Pi /absolute/path/to/star-history-preview
```

For a higher API rate limit, supply `GITHUB_TOKEN` through the environment. Never put the token in a URL or command argument. Run generator tests with `npx vitest run tests/star-history.test.js`.
